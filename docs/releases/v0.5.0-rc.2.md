# MoveMailbox v0.5.0-rc.2

Security and browser-integration update. Prefer this candidate over earlier
previews; it is not a public-hosting readiness guarantee.

## Fixed

- Go 1.27.3 security patch level in CI, native builds and pinned Docker builder;
  SQLite/x/sys and npm dependency refresh, with zero reachable Go/production npm
  advisories in the audit scans.
- Browser cancellation now sends the JSON header/body required by the API.
- Destructive mirror confirmation resets when provider/security/port selections
  change, not just when somebody types into a textbox.
- Cancelled views retain last observed transferred/skipped/byte counters. These
  are partial observations, not an exact final provider-side inventory.
- Windows-compatible static export/CSP generation; valid source type-check
  command, coordinated React updates and consistent download entry points.
- Bounded private operator monitoring and safer retained-lab subnet allocation.
- Explicit supported Webpack production builds after final Pages CI exposed a
  Turbopack font-resolution failure; fonts and design are unchanged.

## Verification

Race-enabled Go tests/vet/vulnerability scan, Python operational tests, SDK and
mirror regressions, website export/type checking and exact-source Docker gates.
The release workflow additionally validates archives and starts the packaged
Windows/Linux demo before publication. ARM/macOS are cross-built, not natively
exercised.

The reviewed closed-stage runtime passed a real external HTTPS/worker attachment
copy, zero-copy repeat, matching body hash/flags/date and unchanged source. A
bounded 80-request/four-client gateway test verified rate limiting and recovery.
Windows browser demo verified reload, cancellation and preserved partial counts.
See [launch audit](https://github.com/Anton-Babaskin/MoveMailbox/blob/main/docs/LAUNCH-READINESS.md)
for evidence boundaries and the remaining production decisions.

## Still explicit

Native packages require a separately installed compatible imapsync; Docker
bundles the pinned engine. Windows real-IMAP acceptance is not replaced by a demo.
Previews are unsigned/not notarized. A stable release requires the owner's
distribution-license decision. Guest-first public hosting, paid accounts,
outbound alerts and automatic certificate renewal are not implied by this tag.
