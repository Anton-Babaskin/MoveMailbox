# MoveMailbox: платный кабинет — концепция для Claude

Статус: предложение по UX и контракту backend, не реализованный кабинет.
Сайт и визуальная реализация остаются у Claude. Основная идея: «мой перенос
под контролем». Пользователь должен сразу видеть, что происходит и что делать.

## Вход и покупка

Бесплатный перенос остаётся без регистрации. При покупке пользователь указывает
email; после подтверждённой оплаты система создаёт или связывает покупку с
профилем. Вход — одноразовой ссылкой на этот email. Адрес покупки нельзя считать
подтверждённым до открытия ссылки; наличие email не даёт права видеть историю.
Первое открытие кабинета сразу показывает купленную услугу и кнопку переноса.
Оплата со статусом «обрабатывается» не выдаёт права до подтверждения провайдером.
Пилотный Basic Auth не является реализацией этого входа.

## Навигация и стартовый экран

Всего три раздела: **Переносы · Покупки · Настройки**. Помощь — постоянная ссылка
справа в шапке. Логотип, переключатели языка/темы, меню профиля; без десятков
пунктов, технических регионов, ключей API и «организаций» для одного человека.

```text
MoveMailbox    Переносы  Покупки  Настройки             Помощь   АБ

Мои переносы                                    [+ Новый перенос]
Доступно по вашей покупке: [реальные условия]       Детали покупки
```

На мобильном — одна колонка, табличные строки становятся карточками с названием,
статусом и основным действием. Основная кнопка доступна без горизонтальной прокрутки.

## Визуальное направление

Спокойный продуктовый интерфейс: светлый фон #F6F8FA, белые поверхности, графитовый
текст #17212B, тёмно-бирюзовая основная кнопка #087F72 с белой надписью. В тёмной
теме — фон #101820 и поверхности #17232E. Цветовые значения — стартовые кандидаты;
Claude проверяет контраст WCAG AA для текста, ошибок, границ и focus-состояний.
Один акцент, тонкие разделители, радиусы 12–16 px, системный sans-serif, нормальная
плотность текста. Иконки сопровождаются подписями; состояние различается и текстом.
Анимация короткая и функциональная, с учётом prefers-reduced-motion. Сохранять
выбор light/dark/system и языки RU/EN/UK. Не добавлять графики ради украшения.

## Детали переноса

Одна страница: итоговый статус, источник/назначение, фактический прогресс, текущая
папка, события. Журнал внизу раскрывается кнопкой «Технические подробности»;
паролей и токенов в нём нет. Полный email виден только владельцу в деталях,
на обзорных карточках достаточно понятного названия и серверов.

- Состояния: проверка → оценка → очередь → копирование → готово/ошибка/отменено.
- При неизвестном общем объёме показывать этап и фактические счётчики без %.
- Скорость и оставшееся время выводить только после реализации надёжного расчёта.
- «Отменить» требует подтверждения; честно пояснять, что уже скопированные письма
  останутся. Кнопки паузы нет, пока backend её не поддерживает.
- «Повторить» открывает подтверждение настроек и при необходимости запрашивает
  пароли заново. Отменённое задание не превращается незаметно в новый перенос.
- Строгое зеркало — в расширенных настройках, красное предупреждение, checkbox
  понимания последствий и отдельное подтверждение. Автоповтор запрещён.
- Ошибка: человеческое объяснение, затронутый сервер, одно следующее действие.
  При проблемах сети: «Связь с сервисом потеряна. Обновляем статус», а не ложный
  статус «перенос остановлен». Перезагрузка восстанавливает существующее задание.

## Покупки и отличие платного опыта

Каждая покупка — карточка с точными правами: объём, число ящиков, срок действия
и остаток, только если они есть в оплаченной модели. Отдельно квитанция/счёт и
статус оплаты. Не показывать «баланс кредитов», пока пользователь не покупает
именно кредиты. Не обещать ускорение/приоритет, пока очередь этого не обеспечивает.

Начальная модель: «Разовый перенос»; позднее «Команда» с пакетными заданиями и
ролями. Разовый покупатель видит простой кабинет; командный раздел появляется
после подключения командного продукта. Конкретные цены здесь не утверждаются.
История, защищённый отчёт и восстановление доступа через email — понятная ценность;
не делать бесплатные переносы искусственно неудобными. Донаты — отдельная
добровольная поддержка, без неявных платёжных прав.

## Состояния, которые обязательно нарисовать

Пустой кабинет после первой покупки; один активный перенос; готовый перенос;
ошибка входа в ящик; ошибка оплаты; платёж ещё обрабатывается; исчерпанные права;
истёкшая magic link; потеря соединения; мобильный экран. Не заменять эти состояния
идеальным dashboard с выдуманными числами. Все демонстрационные данные помечать.

## Контракт для backend и порядок реализации

1. Профили и magic link: хеш токена в хранилище, ограниченный срок, однократное
   использование, лимит попыток, нейтральный ответ на запрос входа, защищённая
   cookie и CSRF. Погашение ссылки явным действием, чтобы почтовый сканер не
   расходовал её раньше пользователя. Редиректы только на разрешённые пути.
2. Платёжные события с проверкой подписи и идемпотентностью; права только из
   подтверждённого server-side события, не из URL страницы «успех». Повторное
   событие не выдаёт повторные права. Возврат имеет явную политику отзыва прав.
3. Связь задания с владельцем и покупкой: проверка доступа на каждом запросе,
   отчёте и потоке событий. Чужая покупка/история недоступна по подменённому ID.
   Привязка гостевого задания требует одновременно гостевой сессии и подтверждённого
   профиля, простого совпадения email недостаточно.
4. UI трёх разделов, после этого реальные платёжные тесты и один полный сценарий
   покупки → входа → переноса → отчёта. Общая админка сервиса — отдельный интерфейс.

Сейчас есть guest API, worker и pilot gate. Постоянные платные профили, magic link,
billing и описанный кабинет нельзя представлять готовыми до реализации/проверки.
SEO у публичных страниц; приватный кабинет — noindex, приватное кеширование и
серверная авторизация. Предсказуемый URL не должен раскрывать персональные данные.
